- 5,882,221,452 bytes; 2,167,558 complete four-line records
- SHA-256 `d4f25be6d726628d14b77619fab275f0d9044872d7a9275a4d95fe41656e6b33`
- no structural, alphabet, truncation, or sequence/quality-length errors
- length median 1,232 nt; q5–q95 294–1,395 nt; extreme range 0–404,266 nt
- per-read mean-Q median 39.87

Consequently, the notebook's displayed 1,500-nt minimum would discard at least
95% of this file. The initial profile does not impose a length gate.

Exact RP evidence (trim 8 from both primer ends, both strands, head/tail 400 nt)
was RP01 95,868; RP02 35,991; RP03 11,778; RP04 27; RP05 312; RP06 431,653;
RP07 270,607; RP08–RP12 zero. Predominant head-reverse-complement and
tail-forward hits confirm that raw reads occur in both orientations.

## Bounded pilot

A deterministic 20,000-record diagnostic FASTQ was generated by uniform source
byte offsets and record resynchronization. It is length-biased and must not be
used to estimate biological frequencies. Its SHA-256 is
`a2e4e2986fe13fa6ea9f7a588107f551007084edb1e0ef011567036e5ca54710`.

The corrected immutable run `20260506-lab-biotin-pilot-20k-rp07-corrected`
completed all six stages:

- plate assigned 16,050/20,000; conflicting 348; ambiguous 9; unassigned 3,593
- plate+well assigned 5,440; well unassigned after plate call 10,610
- assignment: 4,401 unique, 38 ambiguous, 273 motif-missing, 728 no-match
- portable consensus: 99 pass, 53 heterogeneous, 1,589 low-depth
- QC: 39 pass, 113 fail, 1,589 not evaluable because depth was below six
- measured time: demultiplex 299 s; assignment 76 s; consensus 1 s

The diagnostic sample has insufficient depth for most plate/well/reference
groups, so the low-depth proportion is expected and does not estimate the full
run's yield. However, well matching rejects two thirds of plate-called reads and
is the first threshold/primer representation to calibrate. A production run at
the measured demultiplex rate would take roughly nine hours on this Mac, so the
demultiplexer requires optimization before full-scale execution.

## Legacy-compatible optimisation follow-up

The optimisation notebook was subsequently audited cell by cell. A new
immutable run, `20260506-lab-biotin-pilot-20k-legacy-optimised`, uses the
recovered conservative RP settings (`12/400/6`, threshold-unique calling) and
rescored well settings (`12/400/7`, active production unique-best calling). It
does not alter or replace either earlier pilot.

Compiled barcode panels, edit cutoffs, an A/C/G/T fast path and bounded in-memory
batches reduced the complete demultiplex stage from 299 to 55 seconds (5.4×),
including FASTQ parsing and deterministic compressed output writes. Its counts
were 15,126 assigned, 2,032 plate-unassigned, 34 plate-ambiguous, 2,807
well-unassigned and one well-ambiguous. Downstream assignment produced 12,145
unique, 107 ambiguous, 973 motif-missing and 1,901 no-match calls; portable
consensus produced 603 pass, 149 heterogeneous and 1,731 low-depth groups; QC
reported 286 pass, 466 fail and 1,731 not-evaluable.

The increase from 5,440 to 15,126 demultiplexed reads is a scientific policy
change, not merely a speedup. The sweep used proxy labels from earlier runs and
did not provide per-read ground truth, so the profile remains a strong
legacy-compatible candidate rather than a universally validated optimum. See
`demultiplex_optimisation.md` for the exact alternatives and caveats.

## Consensus backend comparison

Nanopore2 used MAFFT followed by SPOA. Nanopore3 now implements that exact command
chain as the optional `mafft_spoa` backend while retaining the cross-platform
reference-guided edlib pileup as `portable`.

For the three deepest eligible groups from RP01, RP05, RP06, and RP07 (12 groups),
portable and MAFFT→SPOA consensus identities to each other were 0.9692–0.9860.
Portable QC passed 5/12; MAFFT→SPOA passed 0/12 at the strict 0.98 threshold.
In every sampled group MAFFT→SPOA emitted a sequence six bases longer, consistent
with systematic retained flanking sequence. Therefore `portable` remains the
default pending a corrected insert-boundary comparison and broader benchmark;
backend choice is explicit and recorded.

## Issues found and fixed during the pilot

- barcode trimming previously removed bases only from the start; it now trims
  both ends, matching the notebook semantics
- reference assignment now uses a separate index per plate-routed library
- unmapped plates receive an explicit reason code instead of being guessed
- optional MAFFT/SPOA tools are checked before a scientific run starts
- QC CSV now has a fixed schema; the initial immutable pilot exposed that a
  low-depth first row had caused alignment metric columns to be omitted
- run metadata now records Git commit and dirty state

The original Nanopore2 repository and source sequencing/reference files were not
modified.
